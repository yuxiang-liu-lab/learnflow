Source was downloaded for inspection only; none was executed, installed, or copied into the extension. These are architectural references, not evidence of compatibility with the user's quiz.

## Decisions for implementation

1. **DOM adapter:** inspect an actual text question and frame structure before writing selectors. Produce a plain-data question record containing the prompt, ordered choices, instructions, relevant visible context, and audio state. Ambiguous or incomplete extraction blocks analysis.
2. **Panel:** one isolated, collapsible right-side panel. Render model output as text. Check panel placement against actual question/choice rectangles; use a collapsed state when space is insufficient. No changes to quiz controls or their listeners.
3. **Worker:** validate sender, message shape, and size; load credentials from trusted extension storage. Content scripts receive only public configuration/status and validated results. Credentialed API calls belong in the worker.
4. **Question lifecycle:** observe the verified question area, debounce rendering changes, and fingerprint normalized prompt, ordered choices, instructions/context, question identity, and associated media identity. Exclude the assistant panel and transient player time. Clear stale suggestions immediately; ignore results from old request generations. Bound in-flight work and allow explicit retry after errors.
5. **Audio gate:** inspect a real listening question before implementing retrieval. Record how its player relates to that question and how the exact excerpt is delivered, including any start/end boundaries. Fetching unrelated audio or merely obtaining a URL is insufficient. Require successfully obtained, supported audio to be included in the model analysis. If unavailable, show: “Audio unavailable — cannot reliably answer this listening question.” No text-only fallback for listening questions. Speech transcription alone does not supply musical evidence.
6. **Validation:** verify response structure, answer membership, explanation type, and finite confidence within 0–1. Display canonical answer text from the extracted choices. Never select, advance, or submit.

These lifecycle and audio safeguards are our design decisions; the references do not establish a verified Cengage listening-question pipeline. Select and verify current API/model capabilities during the API phase rather than inherit the repositories' model defaults.
